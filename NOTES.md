## Фаза 0 — главное (2026-10-03; подробности docs/protocol.md)
- ИГРУ ЗАПУСКАЕТ НЕ ЛАУНЧЕР, А `SS14.Loader.exe` (.NET 10, из репо оф. лаунчера, MIT). Грузит Robust.Client.dll из engine-zip, читает контент прямо из `content.db`. Rust-ядро его заменить не может -> нужен Loader + .NET 10 runtime (вариант A: собирать из исходников). РЕШЕНИЕ ПОЛЬЗОВАТЕЛЯ ПОКА НЕ ПРИНЯТО.
- Схема `content.db` обязана совпадать с оф. (Loader читает её напрямую). Не менять.
- `manifest_hash` = BLAKE2b-256 от всего текста манифеста (проверено живьём). `hash` (zip) = SHA-256 всего zip.
- Оф. лаунчер НЕ проверяет sha256 движка при скачивании; подпись Ed25519 проверяет Loader. Мы проверяем sha256 сами.
- Оф. лаунчер хранит токены открытым текстом в SQLite; мы: Credential Manager/DPAPI. В логи не писать env запуска (там ROBUST_AUTH_TOKEN).
- `signing_key` взят из форка пользователя: сверить с апстримом перед использованием.
- Недоступно с этой машины (таймаут): *.imperialconnect.space (eridani). Для живых тестов брать другие серверы (rmc14 на cdn.rouny-ss14.com отвечает).
- Bash-tool: после `cd` в другую папку cwd сессии «уплывает» (Environment update). Возвращаться в корень проекта в конце команды.

## Шаг 5 (остатки Фазы 1) — ход работы
- Коммиты 5397cce (zip, duplicate, cull, running) и далее (modules, prepare_launch). 129 тестов.
- zip-режим: качаем во временный файл (tmp\), sha256, затем каждый файл как в manifest-режиме; одна транзакция. НА ЖИВОМ СЕРВЕРЕ НЕ ПРОВЕРЕН (все 12 просмотренных серверов имеют манифест). Идея: `--force-zip` для сверки на lizard (209 МБ) — ждёт согласия на скачивание.
- duplicate_version: тот же хеш под другим fork/version/engine -> новая версия без скачивания; не делается, если меняется движок и есть модули.
- cull: 15 версий всего / 3 на форк / interrupted 7 суток; живой клиент определяется по RunningClient + pid + путь exe (windows-sys QueryFullProcessImageNameW). `bebra running` показывает такие версии. Проверено вживую: после закрытия клиента RunningClient пуст, WAL усечён, код выхода 0.
- Модули: версия = максимальная ≤ engine_version (System.Version.Parse у оф. лаунчера падает на суффиксах типа 264.0.2-fix-physics, у нас суффикс отбрасывается — отличие!). Живьём не проверено (у wizards-testing модулей нет).
- Файлы с правками через python Edit: надёжный способ — скрипт-файл в $TEMP + `python "$(cygpath -w ...)"`, а не `python -c` (кавычки/\r).

## Фаза 2 (авторизация) — ход работы
- Коммит: "core: accounts and login". 157 тестов. ЖИВОЙ ЛОГИН НЕ ПРОВЕРЯЛСЯ: пароль вводит только пользователь в своём терминале (`bebra login`). Намеренно НЕ посылали на auth-сервер выдуманные учётные данные ради проверки формата ответа.
- Что принимали на веру из кода оф. лаунчера (проверить на первом реальном входе): имена полей ответа (token, username, userId, expireTime; newToken), код отказа строкой (InvalidCredentials/TfaRequired/...), 401 на отказ, схема `Authorization: SS14Auth <token>` для ping (ping с мусорным токеном -> 401 проверено живьём).
- Хранение: Windows Credential Manager, цель `BebraLauncher/account/<userId>`, Persist=LOCAL_MACHINE, blob = JSON (user_id, username, token, expire_time), лимит blob 2560 байт. Пароли не сохраняются. Любая программа того же пользователя может прочитать запись — это не сильнее самой учётки Windows (написано в доке модуля).
- Fingerprint (`SS14-Launcher-Fingerprint`) не шлём; решение пользователя принято как «да» (шлём только User-Agent). Если auth отклонит вход без него — вернуться к вопросу.
- Продление: токен продлевается если до истечения < 15 суток; при запуске игры проверяем ping. Сетевая ошибка при проверке не считается смертью токена, если по времени он ещё жив (предупреждение и запуск с сохранённым).
- Двойная отправка: UrlFallbackSet может отправить POST логина на оба зеркала, если первое не ответило за 3 с (так же делает оф. лаунчер). Оба зеркала — инфраструктура Wizards' Den.
- Токен для клиента передаётся ТОЛЬКО через env (ROBUST_AUTH_*), если auth.mode != Disabled. В логах/describe() скрыт.
- Bash-tool: если приложение закрылось посреди команды, результат неизвестен — сначала проверять git status/состояние файлов.
- ЖИВОЙ ВХОД И ПОДКЛЮЧЕНИЕ ПРОВЕРЕНЫ (2026-10-03, пользователь): `bebra login` прошёл (аккаунт сохранён в Credential Manager, ping/refresh-логика работает), `bebra launch ss14s://lizard.spacestation14.com` запустил клиент, клиент подключился к lizard (UDP 1212, IPv6+IPv4 параллельно), рукопожатие дошло до "Connect denied: The server is full!" (redial=false, delay=30) — т.е. это отказ сервера по заполненности, не по авторизации. Без fingerprint вход работает.

- Тайминги/факты клиента: при ошибке подключения клиент остаётся открытым на экране ошибки (RunningClient жив), пока пользователь не закроет окно.

## Фаза 3: приложение (Tauri 2 + Svelte 5)
- Каркас: `app/` (Vite 8, Svelte 5 runes, TS 5.9, pnpm) + `app/src-tauri` (crate `bebra-app`, в workspace). Запуск: `cd app; pnpm tauri dev`. Сборка UI: `pnpm build` (dist в gitignore, но нужен для `cargo check` — `tauri::generate_context!` требует `app/dist`).
- `core::play::prepare` — общий путь «info → файлы → движок → команда запуска» для CLI и приложения. Future не Send (ContentDb) → в приложении выполняется в отдельном потоке с current-thread runtime (`game.rs`), отмена через `Notify` + `select!`.
- IPC: команды в `commands.rs`; события игры — единый канал `play` (tagged enum `kind`). Токены в UI не передаются никогда (AccountRow: id, имя, срок, состояние). Пароль идёт через IPC только в `login` и сразу на auth-сервер.
- Capabilities: только `core:event:allow-listen/unlisten`; CSP строгая (`default-src 'self'`, connect только ipc). Свои команды доступны без capability (AppManifest не задан).
- Браузерный предпросмотр UI без Tauri: `pnpm dev` + `src/dev-mock.ts` (mockIPC, только в DEV). Размер окна в предпросмотре: 820x560, иначе скриншот обрезает.
- Грабли: класс `.empty` в Svelte-компоненте совпал у двух элементов (scoped CSS по имени класса!). Иконка — заглушка (`icons/source.png`, «B» на градиенте), сгенерирована PowerShell/System.Drawing.
- Не сделано в Фазе 3: redial (`--commands`), трей/сворачивание при игре, фильтры по тегам/языку, i18n (строки пока русские прямо в коде).

- НАМЕРЕННО НЕ перенесено из Musya (по просьбе пользователя «не давать понятия чит-функций» — отказ): SideLoad своего кода, скрытие патчера/следов, подмена/сброс/отказ от HWID, кастомные движки и отключение подписи. Это обход банов/античита; переименование в «скрытое/дебаг» этого не меняет. В скрытом debug-разделе: подробный лог, прокси лаунчера, предпросмотр команды запуска, выгрузка Locale для перевода, диагностика, список версий, сброс настроек.
- Скрытый раздел: 7 кликов по версии в Настройках (флаг в localStorage `bebra.debug`).
- Грабли: `$effect`, который читает данные и сам же их пишет, зацикливает страницу и вешает вкладку CDP/браузер (ping effect: теперь `untrack`). Модульный `export type` в .svelte требует `<script module>`. Svelte-компонент без `<script>` не имеет типов для TS (нужен пустой `<script lang="ts"></script>`).
