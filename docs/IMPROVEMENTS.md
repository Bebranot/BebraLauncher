## 0. Правила работы

1. Один пункт — одна ветка/коммит. Проверки из §9, запись в `CHANGELOG.md` по `docs/CHANGELOG_RULES.md`.
2. Не добавлять зависимости без согласия владельца.
3. Не менять схему `content.db`: её читает `SS14.Loader` напрямую.
4. Не логировать токены, пароли и env запуска (`ROBUST_AUTH_*`).
5. Новая строка UI — во всех четырёх локалях (`ru`, `en`, `uk`, `de`); `ru` — эталон.
6. Перед реализацией сверять API с исходниками (`crates/core`, `app/src-tauri`, `app/src`) и, при нужде,
   с `docs/protocol.md`. Не выдумывать поля протокола.
7. Приоритеты: **P0** — ближайший релиз, **P1** — следующий, **P2** — по желанию.
   Сложность: **S** ≤ 1 дня, **M** 1–3 дня, **L** > 3 дней.
8. Пункт помечать «сделано» только при наличии доказательства в коде или git (коммит, файл, тест).
   Неясное оставлять открытым и указывать причину.

### Границы проекта

- Только Windows 10/11 x64; Rust + Tauri 2 + Svelte 5 + .NET Loader.
- Без удалённой автозагрузки DLL-патчей и тихой телеметрии (§7).
- Без Electron и второй БД: 35 МБ и быстрый старт — преимущество.
- `ss14://` по умолчанию только выбирает сервер, не подключается.

## 3. P0 — подробные спецификации

Сделанные пункты оставлены одной строкой; открытые — с проблемой, местом в коде, шагами и приёмкой.

### F01. Watchlist и уведомления по серверам — не сделано

> Статус: не сделано (watchlist в `Settings` нет, notification-плагина нет).

**Проблема.** Чтобы узнать, что на сервере освободился слот или закончился раунд, нужно смотреть на список.

**Где.** `ServerStatus` (`crates/core/src/server.rs`) уже отдаёт `players`, `soft_max_players`, `run_level`,
`round_start_time`, `panic_bunker`. В `Settings` watchlist нет; `tauri-plugin-notification` не подключён.

**Шаги.**
- `Settings.watchlist: Vec<WatchEntry>` (`#[serde(default)]`): `address`, `on_slot`, `on_round_end`, `on_online`, `on_bunker_off`.
- Фоновый опрос только наблюдаемых адресов: 20–30 с, jitter, backoff на ошибках и 429/5xx; пауза при скрытом окне и во время загрузки/игры.
- Сравнивать предыдущее и новое состояние; одно уведомление на переход.
- Клик по уведомлению — показать окно и раскрыть строку сервера. Иконка «наблюдаю» в строке; глобальный выключатель и «только если окно не в фокусе».

**Приёмка.** `players >= soft_max` → `< soft_max`, `run_level` 1→2 или 1→0, offline→online — ровно одно уведомление;
повтор без изменений не спамит; наблюдение переживает перезапуск; сетевые ошибки не уведомляют.
**Риски.** Частота опроса; не опрашивать все ~180 серверов.

### F02. Предзагрузка билда без запуска — не сделано

> Статус: не сделано (IPC `preload` нет).

**Проблема.** Игрок ждёт скачивание и проверку 200+ МБ уже после решения зайти.

**Где.** `play::prepare` (`crates/core/src/play.rs`) возвращает `PreparedGame`; `game::prepare` оборачивает его в поток с прогрессом. IPC `preload` нет.

**Шаги.**
- IPC `preload(address)` и `cancel_preload`: тот же путь, без `launch::spawn` и без обязательного аккаунта.
- Кнопка «Подготовить» в раскрытой строке и в диалоге подключения; бейдж «готово» и размер на диске.
- Опционально: автопредзагрузка избранного через 30–60 с после старта (если игра не запущена), квота диска, участие в cull, согласие на лимитном соединении.

**Приёмка.** Повторный `preload` ничего не качает; прогресс и отмена как у `play`; не меняет `last_account` и не запускает игру; квота соблюдается.

### F03. Предполётная проверка перед загрузкой — частично

> Статус: частично (`check_auth` и проверка места до загрузки есть; `Preflight` и UI нет).

**Есть.** В `play::prepare` после `Stage::Info` (`play.rs:222-229`): `check_auth` (гость на `auth=Required`) и проверка свободного места
(`free_disk_space_bytes`, порог 500 МБ → `PlayError::DiskFull`). Проверка идёт до загрузки.

**Нет.** Структуры `Preflight`; вывода в `ConnectingOverlay` с числами (полнота, `panic_bunker`, свободное место, `engine_version`);
кнопки «Всё равно» для полного сервера (полнота сейчас не проверяется).

**Шаги.** Собрать `Preflight` (`auth.mode`, `panic_bunker`, `players/soft_max`, `build.engine_version`, свободное место);
показать в `ConnectingOverlay` до стадии `files`. Полноту — мягкое предупреждение (данные хаба могут быть старыми).
Точный размер загрузки неизвестен (в манифесте нет размеров): писать «оценка».

**Приёмка.** Гость + `auth=Required` — загрузка не начинается, есть «Войти». Полный сервер — предупреждение с «Всё равно».
Мало места — предупреждение с числами, без подтверждения загрузка не начинается. Нормальный сервер — без заметной задержки.

### F06. Журнал игровых сессий — сделано

`sessions.rs` пишет `record_start` до `app.exit(0)` (`game.rs` ~606, ~613), `record_end` до начисления времени (P1-22),
`recover_sessions` досчитывает при старте (`main.rs:72`). Формат JSON (`active_sessions.json`), не append-only JSONL, как в исходном плане.

### F09. Single-flight обновление токена — частично

> Статус: частично (`token_refresh_lock` и перечитывание есть; теста нет).

**Есть.** `GameState::token_refresh_lock` (`game.rs:98`). `resolve_account` берёт его (`game.rs:482`) и перечитывает аккаунт
из Credential Manager (`store.list()`) до `accounts::ensure_fresh`, поэтому второй поток видит уже обновлённый `expire_time`.

**Нет.** Теста «два параллельных `resolve_account` на near-expiry → один refresh».

**Шаги.** Вынести решение «нужен ли refresh» в функцию, которую можно тестировать без `AppHandle`; добавить тест на один POST при N параллельных вызовах.

**Приёмка.** Один refresh на N параллельных запусков; ошибка refresh не ломает валидный токен; при недоступном auth-сервере поведение прежнее (`NOTES.md`, Фаза 2).

### F14. Трей и поведение закрытия — не сделано

> Статус: не сделано (`TrayIcon` нет).

**Проблема.** Трея нет (`main.rs`, нет `TrayIcon`). Лаунчер, который работает в фоне (обновления, очередь), просится в трей.

**Шаги.**
- `TrayIconBuilder` (Tauri 2, фича `tray-icon`): иконка, tooltip, меню «Открыть», «Избранное → серверы», «Проверить обновления», «Логи», «Выход».
- Настройка `close_behavior`: `exit` (по умолчанию) / `tray`; «запускать свёрнутым в трей».
- Клик по иконке — показать/скрыть окно. При первом сворачивании в трей — уведомление, как выйти.
- Обновление, скачанное в фоне, ставится при явном «Выход».

**Приёмка.** `close_behavior=tray` — крестик не завершает процесс; из трея запускается избранный сервер; иконка и меню читаемы на светлой и тёмной теме Windows.

### F15. Палитра команд `Ctrl+K` — не сделано

> Статус: не сделано.

**Проблема.** Действия разбросаны по вкладкам и диалогам.

**Где.** Глобальные клавиши в `app/src/App.svelte:95-105` (`/`, `Ctrl+F`, `F5`, `Ctrl+R`) — учесть при назначении.

**Шаги.** Оверлей с полем ввода и списком действий и серверов (подключиться, сменить аккаунт, гость, тема, вкладка, обновить, проверить обновления, логи, копировать адрес, в избранное).
Поиск по названию/адресу/тегам; `↑/↓`, `Enter`, `Esc`. Не открывать при фокусе в поле ввода, кроме `Ctrl+K`. Локализация всех пунктов.

**Приёмка.** `Ctrl+K` открывает и закрывает; «corvax» находит сервер, `Enter` открывает диалог подключения (не запускает); работает на 800×500 и при 200% UI scale; конфликтов с `/`, `Ctrl+F`, `F5`, `Esc` нет.

### F23. Виртуализация таблицы — не сделано

> Статус: не сделано (`ServerTable` рендерит все строки).

**Проблема.** При 1000+ строках таблица тормозит (`docs/design-handoff.md`).

**Где.** `app/src/lib/ServerTable.svelte:74` — `{#each rows as server (server.address)}` рендерит все строки.

**Шаги.** Windowed rendering по видимой области + запас 10–20 строк. Раскрытая строка разной высоты: измерять высоты или рендерить раскрытую отдельно.
Сохранять скролл при обновлении списка и при возврате с другой вкладки. Не ломать фокус и клавиатуру (F16). Прототип на 500 строках, затем замер на 2000.

**Приёмка.** 2000 строк — скролл без фризов, память не растёт линейно от числа DOM-узлов; раскрытая строка не «прыгает»; поиск/фильтр/сортировка не теряют позицию без причины; `filters.test.ts` без смысловых правок.
