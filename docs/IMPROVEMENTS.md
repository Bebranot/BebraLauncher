# BebraLauncher — план улучшений

Документ для исполнителя (ИИ-агента). Составлен по чтению кода 2026-10-29.
Сборка и тесты при составлении **не запускались**; всё, что помечено «проверено по коду», —
вывод из исходников, а не из прогона.

---

## 0. Как пользоваться этим документом

1. Работать строго по одному пункту: ветка/коммит на пункт, проверки из §9, запись в `CHANGELOG.md`
   по правилам `docs/CHANGELOG_RULES.md`.
2. Не добавлять зависимости без явного согласия владельца проекта.
3. Не менять схему `content.db`: её читает `SS14.Loader` напрямую.
4. Не логировать токены, пароли и env запуска (`ROBUST_AUTH_*`).
5. Любая новая строка UI — во всех четырёх локалях (`ru`, `en`, `uk`, `de`), `ru` — эталон.
6. Перед реализацией сверять API/поведение с исходниками (`crates/core`, `app/src-tauri`,
   `app/src`) и, если нужно, с `docs/protocol.md`. Не выдумывать поля протокола.
7. Приоритеты: **P0** — ближайший релиз, **P1** — следующий, **P2** — по желанию.
   Сложность: **S** ≤ 1 дня, **M** 1–3 дня, **L** > 3 дней (оценки грубые).

### Границы проекта

- Только Windows 10/11 x64, стек Rust + Tauri 2 + Svelte 5 + .NET Loader.
- Не добавлять: HWID-подмену, обход банов/античита, скрытие следов, отключение проверки подписи,
  удалённую автозагрузку DLL-патчей, тихую телеметрию.
- Не тащить Electron и вторую БД «для удобства»: 35 МБ и мгновенный старт — преимущество.
- `ss14://` по умолчанию только выбирает сервер, не подключается. Не менять без явного решения.

## 1. Снимок текущего состояния

Уже есть (не предлагать как новое):

- Мультихабы (`settings.hubs`, `hub::list_servers_from_hubs`), кэш списка, офлайн-баннер.
- Избранное с алиасами и перестановкой, недавние, история, время игры, заметки к серверам.
- Аккаунты Wizards' Den: пароль не хранится, токен в Credential Manager, авто-продление.
- Загрузка контента: manifest и zip, delta, resume через `InterruptedDownload`, общий `content.db`.
- Движок: скачивание, SHA-256, подпись Ed25519, модули, cull старых версий.
- Запуск через `SS14.Loader`, redial, single instance, сворачивание на время игры, параллельные клиенты.
- Профили оптимизации, окно/UI scale/max FPS, отключение Discord RPC.
- Harmony-патчи (`PatchManager.cs`, вкладка «Моды»), текстовые пакеты `Locale/*.ftl`.
- 18 тем, своя тема, фон/градиент/узор, 4 языка, автозапуск, ссылки `ss14://`.
- Самообновление с GitHub + подпись Ed25519, журнал изменений, скрытый debug-раздел.
- Логи лаунчера с ротацией 1 МБ, диагностика сети, `dump_locale`, `content_versions`.

Известные незакрытые места (из `NOTES.md` и кода):

- Автообновление упирается в приватный репозиторий и токен GitHub.
- Установщик не подписан Authenticode.
- zip-режим, ACZ и модули проверены юнит-тестами, но не вживую.
- Трея нет. Виртуализации таблицы нет. E2E-тестов нет.
- `close_on_play` теряет время сессии. Список «0 = выключено» для автообновления не соответствует коду.

## 3. P0 — подробные спецификации

### F01. Watchlist и уведомления по серверам

**Проблема.** Чтобы узнать, что на любимом сервере освободился слот или закончился раунд, нужно
сидеть и смотреть на список.

**Данные уже есть.** `ServerStatus` (`crates/core/src/server.rs`): `players`, `soft_max_players`,
`run_level`, `round_start_time`, `panic_bunker`. Список обновляется в `store.svelte.ts`.

**Что сделать.**
- В `Settings` добавить `watchlist: Vec<WatchEntry>` с `#[serde(default)]`:
  `{ address, on_slot, on_round_end, on_online, on_bunker_off }`.
- Новый фоновый опрос только наблюдаемых адресов, интервал 20–30 с, jitter, backoff при ошибках,
  пауза при скрытом окне и во время загрузки/игры.
- Сравнивать предыдущее и новое состояние, а не «смотреть на текущее». Уведомление один раз
  на переход.
- `tauri-plugin-notification`; клик по уведомлению — показать окно и раскрыть строку сервера.
- В строке сервера — иконка «наблюдаю».
- Настройки: глобально включить/выключить, «только когда окно не в фокусе».

**Критерии приёмки.**
- Сервер был `players >= soft_max`, стал `< soft_max` → одно уведомление.
- `run_level` 1 → 2 или 1 → 0 → одно уведомление.
- Сервер был offline, стал online → одно уведомление.
- Повторный опрос без изменений не спамит.
- Наблюдение сохраняется между запусками.
- Сетевые ошибки не показываются как уведомления.

**Риски.** Слишком частый опрос; уважать 429/5xx. Не опрашивать все 180 серверов.

### F02. Предзагрузка билда без запуска

**Проблема.** Игрок решает зайти на сервер и только тогда ждёт скачивание/проверку 200+ МБ.

**Что уже есть.** `play::prepare` (`crates/core/src/play.rs`) скачивает контент, движок, модули
и возвращает `PreparedGame`. `game::prepare` оборачивает это в поток с прогрессом.

**Что сделать.**
- IPC-команда `preload(address)` (и `cancel_preload`): тот же путь, но без `launch::spawn`
  и без обязательного аккаунта.
- Кнопка «Подготовить» в раскрытой строке и в диалоге подключения.
- После успеха — бейдж «готово к игре» и размер на диске.
- Автопредзагрузка избранных серверов через 30–60 с после старта, если игра не запущена.
- Настройка «держать готовыми N избранных», квота диска, участие в существующем cull.
- Не запускать предзагрузку на лимитном соединении без согласия.

**Критерии приёмки.**
- Повторный `preload` не скачивает ничего.
- Прогресс и отмена работают так же, как при `play`.
- Предзагрузка не стартует игру и не меняет `last_account`.
- Квота соблюдается, старые версии удаляются по политике cull.

**Риски.** Диск. 10 серверов × 200 МБ. Обязательна настройка и отображение занятого места.

### F03. Предполётная проверка перед загрузкой

**Проблема.** `game::prepare` сначала обновляет аккаунт, затем `play::prepare` идёт в `/info`,
и только потом качает. Проверки «а можно ли вообще зайти» нет: гость на `auth=Required` узнает
об этом после загрузки.

**Что сделать.**
- В `play::prepare` сразу после `Stage::Info` (или в `game::prepare` до `resolve_account`)
  собрать `Preflight`: `auth.mode`, `panic_bunker`, `players/soft_max`, `build.engine_version`,
  свободное место.
- Показывать в `ConnectingOverlay` до стадии `files`: «нужен аккаунт — выберите или войдите»,
  «сервер полон 80/80», «panic bunker: новые игроки могут быть отклонены», «свободно 1,2 ГБ».
- Если `auth=Required`, а аккаунта нет — не начинать загрузку, предложить войти/выбрать.
- Свободное место: `GetDiskFreeSpaceExW` через `windows-sys` (уже в зависимостях `bebra-app`).
- Точный размер manifest-загрузки неизвестен (в манифесте нет размеров). Писать «оценка»
  или использовать `Content-Length` zip. Не выдавать догадку за точность.
- Полноту сервера считать мягким предупреждением: данные хаба могут быть старыми.

**Критерии приёмки.**
- Гость + `auth=Required` → загрузка не начинается, есть действие «Войти».
- Полный сервер → предупреждение, но кнопка «Всё равно» доступна.
- Мало места → предупреждение с числами, загрузка не начинается без подтверждения.
- Проверка не добавляет заметной задержки при нормальном сервере.

### F06. Журнал игровых сессий

**Проблема.** Время игры пишется только после `child.wait()`. При `close_on_play` лаунчер
выходит раньше (`game.rs`), поэтому сессия остаётся с нулём. При закрытии лаунчера во время
игры время тоже теряется.

**Что сделать.**
- Append-only журнал (JSONL или отдельная таблица в новом маленьком SQLite, не в `content.db`):
  `{ id, address, account, pid, started_at, ended_at: null }`.
- При старте игры — запись; при выходе — закрыть.
- При старте лаунчера — найти незакрытые записи, проверить PID (как в cull/RunningClient),
  если процесса нет — закрыть временем последней активности/текущим и доначислить.
- `record_play_time` оставить, но сделать идемпотентным (не двоить).
- `close_on_play`: не выходить, пока не записана стартовая запись; остальное закроет следующий запуск.

**Критерии приёмки.**
- `close_on_play` + 10 минут игры → после следующего запуска время увеличилось примерно на 10 минут.
- Убийство лаунчера во время игры → время не теряется.
- Одинаковые сессии не учитываются дважды.
- История (`settings.history[].play_seconds`) остаётся совместимой.

### F09. Single-flight обновление токена

**Проблема (вероятная).** `game::resolve_account` в каждом потоке создаёт `CredentialStore`
и вызывает `accounts::ensure_fresh`. При параллельном запуске двух клиентов оба могут сделать
refresh одного токена. Если auth-сервер ротирует токен, один клиент получит уже недействительный.

**Что сделать.**
- В `AppState` добавить `refresh_locks: Mutex<HashMap<Uuid, Arc<tokio::sync::Mutex<()>>>>`
  (или один `tokio::sync::Mutex<()>` на все аккаунты — проще).
- Внутри блокировки **перечитать** аккаунт из Credential Manager и проверить `expire_time`;
  если другой поток уже обновил — использовать новое значение, не делать второй POST.
- Тест: два параллельных `resolve_account` на near-expiry аккаунте → ровно один refresh.

**Критерии приёмки.**
- Один refresh на N параллельных запусков.
- Ошибка refresh не ломает уже валидный токен.
- Поведение при недоступном auth-сервере не меняется (`NOTES.md`, Фаза 2).

### F14. Трей и поведение закрытия

**Проблема.** `main.rs` не создаёт трей. `minimize_on_play` сворачивает в панель задач.
Лаунчер, который живёт фоном и качает/проверяет обновления, просится в трей.

**Что сделать.**
- `TrayIconBuilder` (Tauri 2, фича `tray-icon`): иконка, tooltip, меню.
- Меню: «Открыть», «Избранное → серверы», «Проверить обновления», «Логи», «Выход».
- Настройка `close_behavior`: `exit` / `tray` (по умолчанию `exit`, чтобы не менять привычку).
- Настройка «запускать свёрнутым в трей»; объединить с существующим автозапуском.
- Клик по иконке — показать/скрыть окно; второй запуск exe — фокус (см. B05).
- Не скрывать в трей без уведомления при первом закрытии («свернулся в трей, выйти можно здесь»).

**Критерии приёмки.**
- Закрытие по крестику при `close_behavior=tray` не завершает процесс.
- Из трея можно запустить избранный сервер.
- Обновление, скачанное в фоне, устанавливается при явном «Выход».
- Иконка и меню корректны на светлой/тёмной теме Windows.

### F15. Палитра команд `Ctrl+K`

**Проблема.** Действия разбросаны по вкладкам и диалогам; для «минимума заморочек» нужен один вход.

**Что сделать.**
- Оверлей с полем ввода и списком: действия + серверы.
- Действия: подключиться к серверу, сменить аккаунт, гость, тема, вкладка, обновить список,
  проверить обновления, открыть логи/данные, скопировать адрес, добавить в избранное.
- Поиск по названию/адресу/тегам; `↑/↓`, `Enter`, `Esc`.
- Не открывать, когда фокус в поле ввода, кроме `Ctrl+K`.
- Локализация всех пунктов.

**Критерии приёмки.**
- `Ctrl+K` открывается и закрывается с клавиатуры.
- Ввод «corvax» находит сервер, `Enter` открывает диалог подключения, а не запускает сразу.
- Работает на 800×500 и при UI scale 200%.
- Нет конфликтов с `/`, `Ctrl+F`, `F5`, `Esc`.

### F23. Виртуализация таблицы

**Проблема.** `ServerTable` рендерит все строки. 180 работает, 1000+ может тормозить
(прямо отмечено в `docs/design-handoff.md`).

**Что сделать.**
- Windowed rendering по видимой области + запас 10–20 строк.
- Строки разной высоты из-за раскрытой строки: либо измерять реальные высоты,
  либо виртуализировать только свёрнутые, а раскрытую рендерить в потоке.
- Сохранить скролл при обновлении списка и при возврате с другой вкладки.
- Не ломать `{#key app.tab}` и фокус/клавиатуру (F16).
- Замерить: 2000 строк, поиск, скролл, раскрытие.

**Критерии приёмки.**
- 2000 строк: скролл без заметных фризов, память не растёт линейно с числом DOM-узлов.
- Раскрытая строка не «прыгает».
- Поиск/фильтр/сортировка не теряют позицию без причины.
- Тесты `filters.test.ts` не меняются по смыслу.

**Риски.** Svelte scoped CSS и динамические высоты. Сначала прототип на 500 строках.

### F24. Версия схемы и бэкап настроек

**Проблема.** `Settings::load` делает `serde_json::from_slice(...).ok()` → при любой ошибке
возвращает дефолт. Избранное, история, заметки и хабы исчезают молча.

**Что сделать.**
- Добавить `schema_version: u32` (текущая = 1) в `Settings`.

### F34. Доставка обновлений без GitHub-токена

| B06 | `main.rs` | `RunningClient` не читается при старте | живые клиенты видны после падения лаунчера |
| B07 | `crates/core/src/server.rs` | `ping_server` — RTT HTTP `/status`, а UI говорит «пинг» | подпись/tooltip «HTTP»; нет ложного ожидания игрового пинга |
| B08 | `app/src/lib/SpaceBackground.svelte` | canvas не проверяет `prefers-reduced-motion` | фон статичен при reduced motion |

B04 и B06 требуют воспроизведения до правки. B05 проверить на собранном exe (не в dev-режиме).
