## 0. Правила работы

1. Один пункт — одна ветка/коммит. Проверки из §9, запись в `CHANGELOG.md` по `docs/CHANGELOG_RULES.md`.
2. Не добавлять зависимости без согласия владельца.
3. Не менять схему `content.db`: её читает `SS14.Loader` напрямую.
4. Не логировать токены, пароли и env запуска (`ROBUST_AUTH_*`).
5. Новая строка UI — во всех четырёх локалях (`ru`, `en`, `uk`, `de`); `ru` — эталон.
6. Перед реализацией сверять API с исходниками (`crates/core`, `app/src-tauri`, `app/src`) и, при нужде,
   с `docs/protocol.md`. Не выдумывать поля протокола.
7. Приоритеты: **P0** — ближайший релиз, **P1** — следующий, **P2** — по желанию.
   Сложность: **S** ≤ 1 дня, **M** 1–3 дня, **L** > 3 дней.
8. Пункт помечать «сделано» только при наличии доказательства в коде или git (коммит, файл, тест).
   Неясное оставлять открытым и указывать причину.

### Границы проекта

- Только Windows 10/11 x64; Rust + Tauri 2 + Svelte 5 + .NET Loader.
- Без удалённой автозагрузки DLL-патчей и тихой телеметрии (§7).
- Без Electron и второй БД: 35 МБ и быстрый старт — преимущество.
- `ss14://` по умолчанию только выбирает сервер, не подключается.

## 1. Снимок текущего состояния

Уже есть (не предлагать как новое):

- Мультихабы (`settings.hubs`, `hub::list_servers_from_hubs`), кэш списка, офлайн-баннер.
- Избранное с алиасами и перестановкой, недавние, история, время игры, заметки к серверам.
- Аккаунты Wizards' Den: пароль не хранится, токен в Credential Manager, авто-продление.
- Загрузка контента: manifest и zip, delta, resume (`InterruptedDownload`), общий `content.db`.
- Движок: скачивание, SHA-256, подпись Ed25519, модули, cull старых версий.
- Запуск через `SS14.Loader`, redial, single instance, параллельные клиенты.

  `unload_on_play`, по умолчанию включена; 1.0.200). Сворачивание на время игры (`minimize_on_play`).
- Предполётная проверка до загрузки: авторизация (`check_auth`) и свободное место 500 МБ (`play.rs`, `prepare`); `play::plan` для CLI.
- Профили оптимизации (четыре профиля, 18 переключателей), окно/UI scale/max FPS, режим Discord RPC (игра, лаунчер, откл).
- Harmony-патчи (`PatchManager.cs`, вкладка «Моды») с SHA-256 (P1-2); текстовые пакеты `Locale/*.ftl`.
- 18 тем, своя тема, фон/градиент/узор, 4 языка, автозапуск, ссылки `ss14://`.
- Самообновление с публичного репозитория GitHub без токена, подпись Ed25519, журнал изменений, скрытый debug-раздел.
- Логи с ротацией 1 МБ, сетевая диагностика (`commands::diagnostics`), `dump_locale`, `content_versions`.
- Журнал сессий (`sessions.rs`, `active_sessions.json`), `settings.json.bak` и карантин, HWID (`hwid.rs`).
- Экспорт и импорт настроек (JSON без токенов: настройки, избранное, его имена и заметки; файлом или через буфер).
- Автоочистка старых сборок при занятых более 5 ГБ, портативный режим (`portable.txt`).

## 3. P0 — подробные спецификации

Сделанные пункты оставлены одной строкой; открытые — с проблемой, местом в коде, шагами и приёмкой.

### F01. Watchlist и уведомления по серверам — не сделано

> Статус: не сделано (watchlist в `Settings` нет, notification-плагина нет). Одобрено владельцем, в плане следующим.

**Проблема.** Чтобы узнать, что на сервере освободился слот или закончился раунд, нужно смотреть на список.

**Где.** `ServerStatus` (`crates/core/src/server.rs`) уже отдаёт `players`, `soft_max_players`, `run_level`,
`round_start_time`, `panic_bunker`. В `Settings` watchlist нет; `tauri-plugin-notification` не подключён.

**Шаги.**
- `Settings.watchlist: Vec<WatchEntry>` (`#[serde(default)]`): `address`, `on_slot`, `on_round_end`, `on_online`, `on_bunker_off`.
- Фоновый опрос только наблюдаемых адресов: 20–30 с, jitter, backoff на ошибках и 429/5xx; пауза при скрытом окне и во время загрузки/игры.
- Сравнивать предыдущее и новое состояние; одно уведомление на переход.
- Клик по уведомлению — показать окно и раскрыть строку сервера. Иконка «наблюдаю» в строке; глобальный выключатель и «только если окно не в фокусе».

**Приёмка.** `players >= soft_max` → `< soft_max`, `run_level` 1→2 или 1→0, offline→online — ровно одно уведомление;
повтор без изменений не спамит; наблюдение переживает перезапуск; сетевые ошибки не уведомляют.
**Риски.** Частота опроса; не опрашивать все ~180 серверов.

### F02. Предзагрузка билда без запуска — не сделано

> Статус: не сделано (IPC `preload` нет). Одобрено владельцем, в плане следующим.

**Проблема.** Игрок ждёт скачивание и проверку 200+ МБ уже после решения зайти.

**Где.** `play::prepare` (`crates/core/src/play.rs:191`) возвращает `PreparedGame`; `game::prepare` (`app/src-tauri/src/game.rs:349`) оборачивает его в поток с прогрессом. IPC `preload` нет.

**Шаги.**
- IPC `preload(address)` и `cancel_preload`: тот же путь, без `launch::spawn` и без обязательного аккаунта.
- Кнопка «Подготовить» в раскрытой строке и в диалоге подключения; бейдж «готово» и размер на диске.
- Опционально: автопредзагрузка избранного через 30–60 с после старта (если игра не запущена), квота диска, участие в cull, согласие на лимитном соединении.

**Приёмка.** Повторный `preload` ничего не качает; прогресс и отмена как у `play`; не меняет `last_account` и не запускает игру; квота соблюдается.

### F03. Предполётная проверка перед загрузкой — частично

> Статус: частично (`check_auth` и проверка места до загрузки есть; `Preflight` и UI-вывода нет). Одобрено владельцем, в плане следующим.

**Есть.** В `play::prepare` после `Stage::Info` (`crates/core/src/play.rs:222-228`): `check_auth` (гость на `auth=Required`) и проверка свободного места
(`free_disk_space_bytes`, порог 500 МБ → `PlayError::DiskFull`). Проверка идёт до загрузки.
Функция `play::plan` (`play.rs:156`) делает то же без установки и возвращает `LaunchPlan`, но вызывается только из CLI (`crates/cli/src/main.rs:588`); в UI не подключена.
`ConfirmConnectDialog.svelte:24` показывает `players / soft_max_players`.

**Нет.** Структуры `Preflight`; вывода в `ConnectingOverlay` с числами (полнота, `panic_bunker`, свободное место, `engine_version`);
кнопки «Всё равно» для полного сервера (полнота сейчас не проверяется).

**Шаги.** Собрать `Preflight` (`auth.mode`, `panic_bunker`, `players/soft_max`, `build.engine_version`, свободное место), на базе `play::plan`;
показать в `ConnectingOverlay` до стадии `files`. Полноту — мягкое предупреждение (данные хаба могут быть старыми).
Точный размер загрузки неизвестен (в манифесте нет размеров): писать «оценка».

**Приёмка.** Гость + `auth=Required` — загрузка не начинается, есть «Войти». Полный сервер — предупреждение с «Всё равно».
Мало места — предупреждение с числами, без подтверждения загрузка не начинается. Нормальный сервер — без заметной задержки.

### F06. Журнал игровых сессий — сделано

`sessions.rs` пишет `record_start` до `app.exit(0)` (`game.rs:644`, `653`), `record_end` (`game.rs:686`) до начисления времени (P1-22),
`recover_sessions` досчитывает при старте (`main.rs:79`). Формат JSON (`active_sessions.json`), не append-only JSONL, как в исходном плане.

**Есть.** `SpaceBackground.svelte` уважает `prefers-reduced-motion` (B08); тест контраста тем (`themes.test.ts`, P1-23, P2-49); `tablist`, `aria-sort`, `role=switch` (P2-51, P2-55); `aria-live` в `ModsTab.svelte:203` и `UpdatesTab.svelte:80`.

**Нет (FIXLOG P2-56, P2-57).** `aria-live` для тостов (`Toast.svelte`) и стадий подключения; menu-семантика; подтверждение выхода; текст/иконка для пинга и полноты (не только цвет); полная проверка `aria-label` у иконок.

**Приёмка.** Тест контраста зелёный; навигация скринридером по ключевым экранам; проверка 200% UI scale и 800×500.

### F20. Окно: клампинг и фокус — частично

> Статус: частично (`restore_window` при втором запуске есть; клампинга к монитору нет).

**Есть.** Второй экземпляр без аргументов вызывает `game::restore_window` (`handle_launcher_args`, `commands.rs:832`, B05). Плагин `tauri-plugin-window-state` подключён (`main.rs:138`).

**Нет.** Клампинга позиции к рабочей области ближайшего монитора (multi-monitor/DPI). Опционально: своя titlebar (`docs/design-handoff.md`), только после P0.

**Приёмка.** Отключили второй монитор — окно видно; повторный запуск exe поднимает свёрнутое окно (есть по коду, проверить на exe).

### F25. Генерация TS-типов — не сделано

> Статус: не сделано (`ts-rs` и `tauri-specta` нет ни в одном `Cargo.toml`). На усмотрение мейнтейнера.

`app/src/lib/api.ts` вручную повторяет `commands.rs`.

**Шаги.** Зафиксировать текущий контракт; ввести `ts-rs` или `tauri-specta`; CI: генерация + `git diff --exit-code`. Не менять имена полей на лету.

**Приёмка.** Поле в Rust без правки TS валит CI; существующий UI собирается без изменений.

### F26. Пауза, лимит, параллельные потоки — не сделано

> Статус: не сделано (в `download.rs` нет ни паузы, ни лимита скорости, ни параллельных потоков). `download_blobs` в `updater.rs` есть.

**Шаги.** «Пауза» = отмена `prepare` с сохранением проверенных блобов, «Продолжить» = повторный `prepare`; UI пишет, что прогресс сохранён.
Лимит скорости — token bucket поверх `bytes_stream` (`download.rs`); автопауза при запущенной игре. Параллельные потоки — только после бенчмарка (CDN может уже насыщать канал).

**Приёмка.** Пауза/продолжение не качает заново; лимит держится ±10%; параллельный режим не портит транзакции и не дублирует блобы.

### F27. Один планировщик обновления — частично

> Статус: частично (единый таймер и пауза при скрытом окне есть; jitter, backoff, ETag нет).

**Есть.** `restartAutoRefresh` (`app/src/lib/store.svelte.ts:746-765`): один таймер, `0` выключает (B02), пауза при `visibilityState !== "visible"`, не опрашивает во время подготовки игры (`play.phase !== "preparing"`).

**Нет.** jitter, backoff на 429/5xx, ETag/If-None-Match (если хаб поддерживает). Для F27 см. также B02.

### F28. Канонизация адресов и лимиты хабов — частично

> Статус: частично (лимиты и HTTPS есть; слияние хабов не канонизирует адреса; теста дедупликации нет).

**Есть.** `MAX_HUB_LIST_BYTES` = 8 МБ (`crates/core/src/hub.rs:23`), `MAX_HUB_SERVERS` = 5000 (`hub.rs:25`); `is_valid_hub_url` (HTTPS, localhost); каноническая форма адреса `settings::canonical_address` (`settings.rs:32`) применяется к избранному (`settings.rs:897-899`) и к пингу (`commands.rs:1844`).

**Нет.** Слияние хабов дедуплицирует по строке как пришла (`hub.rs:213`, `entry.address.clone()`), без `canonical_address`. Теста «`ss14s://foo` и `ss14s://foo/` дают одну строку»: не найден.

**Шаги.** Добавить тест дедупликации и применить `canonical_address` при слиянии хабов (`hub.rs`).

**Приёмка.** Дублей нет; гигантский ответ не вешает UI; HTTP-хаб отклоняется с понятной ошибкой.

### F32. Property-тесты и фикстуры — частично

> Статус: частично (фикстуры в тестах `updater.rs` есть; `proptest` не подключён). На усмотрение мейнтейнера.

**Есть.** Фикстуры локальных серверов в тестах `updater.rs` (`struct Fake`, `updater.rs:445`; `struct Cdn`, `updater.rs:767`).

**Нет.** `proptest` не подключён (нет в `Cargo.toml`). Нужны свойства для `ServerAddr::parse`, `split_args` (кавычки, экранирование; два аргумента не склеиваются), `packs` (zip-slip, `..`, абсолютные пути), `news::parse_feed`, `hub` JSON.

**Приёмка.** Тесты стабильны, без сети; падение показывает входные данные.

### F33. Supply chain — частично

> Статус: частично (NuGet-аудит и SHA-пиннинг есть; `cargo-deny`, `pnpm audit`, Dependabot, SBOM нет). На усмотрение мейнтейнера.

**Есть.** Аудит NuGet в `.github/workflows/ci.yml` (`dotnet package list --vulnerable`); действия пиннятся по SHA (P1-42).

**Нет.** `cargo-deny` (нет `deny.toml`), `pnpm audit --prod` в `ci.yml`, Dependabot/Renovate (нет `.github/dependabot.yml`), SBOM (`cargo-cyclonedx`) в `release.yml`.

**Приёмка.** CI падает на новой advisory; SBOM генерируется на теге.
